## Câu hỏi (VI)
Cách bạn ứng xử với một senior dev review code rất khắt khe?

## Question (EN)
How do you handle a very strict senior developer during code review?

## Đáp án chi tiết (VI)
**Nhà PV muốn nghe:** bạn coi review khắt khe là cơ hội học, biết tách phản hồi khỏi cái tôi, nhưng vẫn dám trao đổi khi không đồng ý.\
\
**Tránh:** tỏ ra phòng thủ, hoặc sửa cho qua mà không hiểu vì sao.\
\
**Trả lời mẫu:** \\"Tôi hỏi lý do đằng sau mỗi comment — hiểu cái \\\\\\"vì sao\\\\\\" giúp tôi viết code tốt hơn lần sau chứ không chỉ pass review lần này. Nếu tôi không đồng ý, tôi đưa luận điểm kèm dữ liệu và trao đổi trên tinh thần cùng tìm giải pháp tốt nhất, không phải bảo vệ code của mình.\\"

## Detailed Answer (EN)
**What they're assessing:** that you treat strict reviews as learning, separate feedback from ego, but still speak up when you disagree.\
\
**Avoid:** getting defensive, or silently changing things without understanding why.\
\
**Sample answer:** \\"I ask for the reasoning behind each comment — understanding the \\\\\\"why\\\\\\" helps me write better code next time, not just pass this review. If I disagree, I make my case with data and discuss it as finding the best solution together, not defending my code.\\"
