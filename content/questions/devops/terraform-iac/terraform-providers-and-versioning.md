## Câu hỏi (VI)
Provider trong Terraform là gì? Vì sao cần khóa (pin) phiên bản provider, và file `.terraform.lock.hcl` dùng để làm gì?

## Question (EN)
What is a Terraform provider? Why should you pin provider versions, and what is the `.terraform.lock.hcl` file for?

## Đáp án chi tiết (VI)
**Provider** là một plugin cho phép Terraform "nói chuyện" với một nền tảng cụ thể (AWS, Azure, GCP, Kubernetes, Cloudflare, GitHub...) — dịch resource block trong HCL thành lệnh gọi API thật tới nền tảng đó.

**Khai báo provider:**
```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.30"
    }
  }
}

provider "aws" {
  region = "ap-southeast-1"
}
```

**Vì sao phải pin version:**
- Các provider được phát hành độc lập với Terraform core và **thay đổi thường xuyên** — một bản major mới có thể đổi tên argument, đổi default value, hoặc deprecate resource cũ.
- Nếu không pin (`version = ">= 5.0"` quá lỏng, hoặc không khai báo gì), lần `terraform init` sau trên máy khác/CI có thể tải bản mới hơn và gây **breaking change không mong muốn** — plan đột nhiên báo thay đổi hàng loạt dù code không đổi gì.
- Toán tử phổ biến: `~> 5.30` nghĩa là chấp nhận `>= 5.30.0, < 5.31.0` (khóa theo minor version) — cân bằng giữa an toàn và vẫn nhận patch fix.

**`.terraform.lock.hcl`:**
- Được sinh tự động khi chạy `terraform init`, ghi lại **chính xác phiên bản** và **checksum (hash)** của từng provider đã dùng.
- Mục đích giống `package-lock.json`/`Gemfile.lock` — đảm bảo mọi máy, mọi lần CI chạy `init` đều tải **đúng cùng một phiên bản provider**, tránh "nó chạy được trên máy tôi".
- **Phải commit file này vào Git** (khác với `.terraform/` folder và `terraform.tfstate` — hai thứ đó không commit).
- Khi cố tình muốn nâng version provider, chạy `terraform init -upgrade` để cập nhật lock file theo constraint mới trong `required_providers`.

**Gotcha thường gặp:** Quên commit `.terraform.lock.hcl`, dẫn đến CI pipeline mỗi lần chạy tải provider mới nhất thỏa mãn constraint — có thể pass hôm nay nhưng fail ngẫu nhiên vài tuần sau khi provider ra bản mới có breaking change, rất khó debug vì "không ai đổi gì cả".

## Detailed Answer (EN)
A **provider** is a plugin that lets Terraform "talk" to a specific platform (AWS, Azure, GCP, Kubernetes, Cloudflare, GitHub, etc.) — translating HCL resource blocks into real API calls against that platform.

**Declaring a provider:**
```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.30"
    }
  }
}

provider "aws" {
  region = "ap-southeast-1"
}
```

**Why pin the version:**
- Providers are released independently of Terraform core and **change frequently** — a new major version can rename arguments, change defaults, or deprecate resources.
- Without a pin (`version = ">= 5.0"` is too loose, or no constraint at all), a later `terraform init` on a different machine/CI may pull a newer version and cause an **unexpected breaking change** — the plan suddenly reports a mass of changes even though the code didn't change.
- Common operator: `~> 5.30` means accept `>= 5.30.0, < 5.31.0` (pinned to the minor version) — balances safety with still receiving patch fixes.

**`.terraform.lock.hcl`:**
- Auto-generated by `terraform init`; records the **exact version** and **checksum (hash)** of every provider used.
- Serves the same purpose as `package-lock.json`/`Gemfile.lock` — ensures every machine and every CI run of `init` downloads **the exact same provider version**, avoiding "works on my machine."
- **Must be committed to Git** (unlike the `.terraform/` folder and `terraform.tfstate`, which should not be).
- To intentionally upgrade a provider, run `terraform init -upgrade` to refresh the lock file against the new constraint in `required_providers`.

**Common gotcha:** Forgetting to commit `.terraform.lock.hcl` means every CI run pulls the newest provider satisfying the constraint — it might pass today but fail randomly weeks later when the provider ships a breaking change, which is hard to debug because "nobody changed anything."
